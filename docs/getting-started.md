# 使用指南

本指南从本地启动开始，说明事项规划、Android 小部件、电脑与手机同步，以及备份恢复。所有地址、事项和配置示例均为虚构内容，应替换为自己的设置。

## 1. 启动电脑端

安装 Node.js 22 或更新版本，在项目根目录运行：

```powershell
node --version
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。默认服务仅监听本机，按 `Ctrl+C` 正常停止；关闭浏览器不会停止仍在运行的服务。运行时无需安装 npm 依赖。

Windows 启动器提供前台和后台方式：

```powershell
# 前台运行，停止时按 Ctrl+C
.\Start-Calendar.ps1

# 后台运行并打开浏览器
.\Start-Calendar.ps1 -Open

# 自定义端口
.\Start-Calendar.ps1 -Port 4318 -Open
```

启动器会复用同项目已就绪的服务；遇到端口冲突或仍存在的服务进程会报告错误，不会直接结束其他进程。运行文件保存在项目的 `.local/` 中，后台日志为 `server.stdout.log` 与 `server.stderr.log`。

需要 Windows 桌面快捷方式时，在项目根目录运行：

```powershell
.\Install-Shortcut.ps1
```

该快捷方式会后台启动、打开网页，并启用局域网监听，供手机连接。只使用电脑本机时可继续使用 `Start-Calendar.ps1 -Open`。移动项目后需要重建快捷方式；若已有同名但指向其他项目的快捷方式，脚本会保留它并提示处理。

电脑网页依赖浏览器的 Web Locks 和 Service Worker，请从 `localhost` 或 `127.0.0.1` 打开，保持固定访问地址。同一浏览器一次只使用一个编辑标签页；后开的页面会等待原标签释放编辑权。不要通过双击 `index.html` 打开应用。

## 2. 先录入，再安排

日历下方是常驻的“未安排事项”区域。事项卡片、搜索和筛选位于录入框上方，电脑与手机都使用同一布局。

1. 在“记下一件事”中输入标题，按 Enter 或点击“＋”添加；Shift+Enter 换行。多行内容会先显示批量添加预览。
2. 暂不确定日期时，把事项留在“待安排”。可以搜索标题，或切换“待安排”“待重排”“全部”。
3. 确定日期后，拖到某一天；也可以点击事项，在操作栏选择“安排日期”，再点一天或划选日期范围。可以继续添加其它不连续时间段，最后点“完成安排”。从下方列表安排时，页面会滚回日历。
4. 只知道要在这周完成时，拖到该周的“这周找时间”区域，或在编辑窗口选择“这一周内完成”。周事项独立显示，不占用某一天。

整月适合看月度分布，连续四周适合滚动安排，单周适合查看某一周。每周都保留独立边框和留白。

## 3. 在日历中调整

| 操作 | 方法 |
| --- | --- |
| 新建有日期的事项 | 在空白日期上划选范围，松手填写标题；手机可先在“更多”中开启划选 |
| 添加不连续时间段 | 点击事项，选择“再加一段”；可连续点一天或划选范围，最后点“完成安排” |
| 手机点选日期范围 | 在安排模式点击“点选起止”，依次点开始和结束日期；可以跨周、翻页选择，无需输入日期 |
| 移动安排 | 拖动日历上的一段，只移动该段并保留持续天数；从下方列表拖动则移动整件事的所有段 |
| 改变范围长度 | 拉伸事项两端；紧凑布局先点选事项，再拖动把手 |
| 取消一段或全部安排 | 点击某段后选“移除此段”，或将它拖到下方未安排区域；“取消全部安排”清空整件事的处理时间 |
| 完成、编辑或删除 | 点击事项，在操作栏选择对应动作 |
| 查看完整标题 | 点选事项，在操作栏查看；需要备注与精确日期时打开“编辑” |
| 显示已完成 | 在日历“更多”中开启“显示已完成” |
| 撤销最近操作 | 使用下方事项区域的撤销按钮 |

划选和拖动支持跨周。手机退出划选后可以正常滚动页面；拖动到窗口边缘可滚动。电脑拖动中按 Esc 可取消，尚未松手的预览不会保存为修改。

添加事项时可以勾选“**有截止日**”。如果从某个日历日期进入，该日期会作为截止日，默认不同时安排工作；也可勾选“现在安排处理时间”，选择某一天、一周或连续几天。只记下截止日的事项仍在“待安排”中，之后可拖到日历，或点“安排日期”再划选处理时间。

事项的**计划日期**与**截止日期**分别保存。移动或拉伸计划不会自动修改截止日；编辑窗口也能修改截止日、取消截止或单独取消处理安排。选中事项后点“添加截止日／调整截止日”可以直接在日历点选日期。计划结束超出截止日时会要求确认。

计划结束日期已过的未完成事项会进入“待重排”；硬截止日期已过才标为逾期。撤销会建立新的修改记录，不会清除历史；如果事项已在另一端更新，应用会拒绝旧操作覆盖，请重新打开事项。

## 4. 调整显示

在“设置与同步 → 日历显示”中切换紧凑或宽松布局。手机默认紧凑，电脑默认宽松。

事项字号支持 **6–16 px**，拖动滑条即时预览；日历“更多”中的滑条与设置页同步。紧凑日历标题最多显示两行，选中后可在操作栏阅读完整标题。

这些偏好只影响当前设备，不会同步到其他设备，也不会改变事项历史。Android 桌面小部件有单独的日期、事项字号设置。

## 5. 使用 Android 与桌面小部件

Android 需要从源码构建并安装，见 [Android 说明](../android/README.md)。主日历资源随 APK 打包，安装后无需连接电脑即可使用。

打开“设置与同步 → 添加桌面小部件”，选择“添加普通桌面小部件”并在桌面完成确认。也可以长按桌面空白处，通过系统小部件列表添加“随历 · 月历与四周”。小米澎湃／MIUI 桌面可能需要进入“安卓小部件”分类。

小部件默认请求约 4×3，可长按边框调整宽高；最终占用格数和最小尺寸由桌面决定。应用内的小部件面板提供日期与事项两个 **6–14 sp** 字号滑条，分别默认 9 sp 和 8 sp，修改后自动保存并刷新全部随历小部件。

点击小部件中的日期、周事项或列表入口，会在应用中打开连续四周视图，并定位到相应日期或列表。进入后仍可手动切换整月或单周；小部件自身的月历／四周切换单独保留。

小部件支持月历／四周切换、翻页、周事项和截止日提示；点击日期或事项进入完整日历。缩得过小时会省略部分文字并显示提示，完整内容仍在应用中。系统收到添加请求并不等于已完成绑定，面板可刷新查看状态。

小米小部件中心／负一屏需要独立的平台接入和审核，目前不保证可添加；普通系统小部件的可用性不能作为负一屏验收结果。

## 6. 配置 WebDAV 双端同步

WebDAV 模式下，电脑服务与 Android 分别连接同一个远端文件。使用多段安排前，先将参与同步的电脑服务和 Android 应用全部更新到 **0.5.0 或更新版本**，并在每端导出一份备份。旧客户端会拒绝含多段记录的快照，历史中保留的多段记录也需要新版客户端。

### 准备文件地址

在自己的 WebDAV 服务中建立专用目录，例如 `calendar`，准备一个专用 JSON 文件地址：

```text
https://dav.example.com/calendar/calendar.json
```

这是示例地址。应替换为服务商提供的 WebDAV 地址，填写**完整文件地址**，不要填网页分享链接。父目录需提前建立，JSON 文件可以在首次同步时创建；不要把其他应用的文件当作随历同步文件。

需要可读取、写入文件的权限。地址中不能嵌入用户名密码、查询参数或片段。请使用 HTTPS；HTTP 会明文传输凭据和事项。远端还需要正确支持 ETag 和条件写入，不支持时应用会报错，不会直接改为无条件覆盖。

### 电脑端

1. 启动本地服务，从电脑本机打开日历。
2. 点击顶部“设置与同步”，在 WebDAV 区域勾选“启用 WebDAV 同步”。
3. 填写完整同步文件地址、用户名和密码。
4. 点击“保存并同步”，等待成功状态。之后可通过“立即同步”或顶部同步按钮手动重试。

浏览器通过本机 Node 服务访问 WebDAV，服务商无需为随历额外开放浏览器跨域。当前密码保护依赖 Windows DPAPI，配置迁移到其他用户或系统后需要重新输入密码。

### Android 端

1. 打开“设置与同步 → 同步设置”，将同步方式改为“WebDAV”。
2. 填写与电脑相同的完整文件地址，以及可访问该文件的用户名和密码。
3. 可先点“测试连接”。它只读取并检查日志；文件不存在时会提示首次同步创建，不代表写入已验证。
4. 点击“保存设置”，再点击“立即同步已保存配置”。开启自动同步时，保存也会触发自动请求。

建议先让一端首次创建并同步成功，再连接另一端。用一条虚构事项分别在两端修改，检查双方都能收到结果，再投入日常使用。

### 凭据与同步规则

- 两端分别保存自己的凭据。相同地址、相同用户名下，密码留空可保留已保存密码；更换地址或用户名后需重新输入。
- 匿名服务器可将用户名和密码同时留空。不要把密码放进 URL。
- 电脑关闭启用开关后保存可停用 WebDAV；Android 的“清除 WebDAV 凭据”会停用该连接，保留本地事项与历史。
- 每次同步先读取远端、合并操作，再条件写入并回读确认；其他设备先写入时会重新合并。同一事项出现并发版本时，双方版本都保留，在冲突界面选择。
- 单个同步文件及一次交换上限为 10 MiB。文件损坏、权限不足、缺少父目录或无效 ETag 都会停止同步，应先保留本地数据并处理错误。

电脑服务在修改后和约每 30 秒尝试自动同步，浏览器关闭后只要服务继续运行仍可同步。Android 在回到应用、修改后及系统后台调度时请求同步，后台周期约为 30 分钟，实际时间受系统限制。失败时本地修改仍保留，可恢复网络后手动重试。

## 7. 改用本地电脑同步

不使用 WebDAV 时，可以让手机连接电脑提供的同步服务：

```powershell
# 在项目根目录运行
npm run start:lan
```

也可使用 `Start-Calendar.ps1 -Lan -Open` 后台启动。电脑和手机需要处于可互通的可信网络；按系统提示允许所需的本地网络访问。

1. 在电脑本机打开日历，进入“设置与同步”，查看服务地址和连接码。
2. Android 打开“同步设置”，选择“本地电脑”。
3. 填写电脑的局域网地址和连接码，保存后手动同步一次。

手机的 `127.0.0.1` 指向手机本身，应使用电脑显示的局域网地址。开发调试时可以用 `adb reverse tcp:4317 tcp:4317` 转发 USB 连接，但它不代表 Wi-Fi 已经连通。

本地电脑模式要求电脑服务运行且手机能够访问。关闭电脑后，手机仍可离线查看和修改，重新连接后合并。该服务默认使用 HTTP，只应在可信网络使用；不要直接把本地服务暴露到公网。

## 8. 备份、恢复与离线使用

通过顶部备份按钮导出 JSON；Android 使用系统文件选择器保存。备份包含事项与完整操作历史，包括删除和改期记录，不包含连接码、WebDAV 密码或显示偏好。

导入时先选择文件，检查预览，再确认合并。导入会合并历史，不会直接替换现有事项；出现并发版本时需要选择。建议把备份保存在自己控制的安全位置，定期检查文件可读取，并在升级、重装、清除浏览器数据和更换签名前额外导出。

| 位置 | 保存内容 | 需要注意 |
| --- | --- | --- |
| 浏览器站点存储 | 此浏览器的事项副本、同步确认与显示偏好 | 清除站点数据或无痕会话结束可能丢失本地副本 |
| 电脑 `.local/` | 服务端事项日志、连接码、同步配置与状态 | 不应公开上传；不要通过删除数据文件排查启动问题 |
| Android 应用私有目录 | 手机事项日志、同步状态和加密凭据 | 卸载会清除；不能依靠 Android 自动备份恢复 |
| WebDAV 文件与导出 JSON | 事项及操作历史 | 文件含私人内容，需控制读取权限；不提供端到端加密 |

电脑首次成功打开并缓存界面后，服务暂时不可用时仍可使用已有缓存和本地记录；首次打开和同步仍需要相应服务。Android 日历界面已打包在 APK 中。两端均只保证已提交的事项持久保存，未保存草稿不保证在进程被结束后恢复。

如果页面等待编辑权，先关闭同一浏览器中的另一个日历标签。若服务提示锁或端口占用，先确认原服务是否仍在运行，保留 `.local/`，不要通过清空事项解决。更多构建和排查信息见 [开发指南](development.md)，隐私行为见 [隐私说明](../PRIVACY.md)。
