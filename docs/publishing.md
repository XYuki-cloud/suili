# 导出公开源码

源码导出使用允许清单，范围包括应用源码、构建入口、测试、公开文档、示例图及第三方许可。运行数据、签名、内部开发记录、助手指令和本机编辑器配置均从导出中排除。

## 检查与导出

已提交的源码：

```powershell
npm run privacy:check
node scripts/public-source.mjs export --output ../suili-public
```

准备提交的修改可以先检查和导出暂存区：

```powershell
npm run privacy:check -- --staged
node scripts/public-source.mjs export --staged --output ../suili-public-review
```

目标必须是尚不存在的新目录，位于项目旁边或 `artifacts/` 下。导出前若检测到个人路径、非示例邮箱、常见服务令牌或私钥材料，会报告文件、行号和规则。已提交模式读取 `HEAD`，暂存模式读取 Git 索引，请先确认需要发布的修改已进入相应版本。

`PUBLIC_SOURCE_MANIFEST.json` 记录导出文件的 SHA-256、大小和 Git 文件模式，不包含源目录绝对路径、原 Git 身份或旧提交记录。有 Git 仓库时，清单按所选提交或暂存区的原始 blob 字节生成；克隆后 `.ps1`、`.bat` 可能按 `.gitattributes` 转为 CRLF，核对清单应读取对应 Git blob，不能直接比较转换后的工作区字节。解压后的源码也可运行检查，不要求附带 Git 历史。

## 发布前复核

1. 检查 README、图片和示例是否全为公开内容，单独审阅图片中的事项、通知、地址栏及 PNG 文本和 EXIF 元数据。
2. 从导出目录运行 `npm test`，按 Android 构建说明确认 SDK、JDK 和 Wrapper 配置完整。
3. 核对 `LICENSE`、`NOTICE` 和第三方许可文件已保留。
4. 在导出目录重新初始化 Git，并选择愿意公开的作者身份。发布前检查 `git log --all` 中的提交内容及作者身份，工作区删除文件后，旧提交中仍可能保留该文件。
5. 发布 APK 时另用自己保管的发布签名，签名文件及密码不进入源码、Release 附件或日志。

## 发布目录与历史

公开仓库应从导出的文件建立独立历史。开发目录中的事项、测试记录和旧提交按原用途保管。已有分享副本也需检查全部提交，尤其是曾经加入的截图和文档，不能只检查最新文件。

作者姓名、邮箱、提交说明、分支名称和标签都可能公开。初次发布可使用团队名称与示例邮箱作为通用身份，后续贡献者应自行选择公开身份。

`npm run privacy:check` 检查当前所选的公开文件，人工审阅补充检查真实事项、内部说明、图片内容与历史。源码工具生成本地导出目录后，托管平台的仓库创建、可见性设置和上传由发布者另行操作。
